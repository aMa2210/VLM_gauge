## VLM Gauge – Vision-Language Models for Analog Gauge Reading

**Paper:** [arXiv:2604.22829](https://arxiv.org/abs/2604.22829) — under revision at *IEEE Instrumentation and Measurement Magazine*

This repository explores and evaluates vision-language models on **industrial analog gauge reading** tasks.  
Given gauge videos, the model outputs time-series readings, which are then aligned with encoder-verified ground truth to compute MAE / RMSE / TMS and quantify performance in industrial metrology scenarios.

---

### Dataset

3 gauge types × 3 motion directions × 6 speeds | **[https://zenodo.org/records/20147961]**

> Video files are hosted on Zenodo and not included in this repository. Download and place them under `Dataset/` following the directory structure below.

---

### Features

- **Three gauge types**
  - `Analog Dial Gauge` — circular, dual-dial (large + small)
  - `Analog Depth Gauge` — vernier caliper
  - `Analog Depth Gauge (without vernier)` — simple caliper
- **Two VLM providers**
  - **Gemini** (`gemini-3-flash-preview`, `gemini-3-pro-preview`) — direct video upload
  - **GPT** (`gpt-5.3-chat-latest`, `gpt-5.4-2026-03-05`) — frames extracted via OpenCV, passed as image arrays
- **Two prompt strategies**: CoT (See-Think-Confirm) vs. Naive
- **Auto reading from gauge videos** — outputs a timestamped JSON reading sequence at 1-second intervals
- **Time-aligned accuracy evaluation**
  - **MAE** (Mean Absolute Error)
  - **RMSE** (Root Mean Squared Error)
  - **TMS** (Trend Matching Score)
- **Unified batch inference scripts** — one run covers all gauges × models × strategies automatically

### Ground Truth Label Format

Each label file (`Dataset/*_label/<seq_id>.xlsx`):
- **`Ground_Truth` sheet**: `timestamp_ms`, `encoder_verified_reading`, `motion_state`

Labels are generated by manually annotating a few keypoints and linearly interpolating at 200 ms intervals.

---

### Usage

#### 1. Run inference

**Gemini** — open `Call_Gemini.ipynb` and run all cells. The batch loop automatically iterates all combinations of gauge × model × strategy and saves results to `Results/Gemini/`.

**GPT** — open `Call_GPT.ipynb` and run all cells. Frames are extracted at 1 FPS via OpenCV, resized, and passed as base64 image arrays. Results saved to `Results/GPT/`.

Key config variables (Cell 1 of each notebook):
```python
GAUGE_IDS   = [1, 2, 3]
MODEL_NAMES = ["gemini-3-flash-preview", "gemini-3-pro-preview"]  # or GPT equivalents
STRATEGIES  = ["cot", "naive"]
```

#### 2. Evaluate

Open `Analyse.ipynb` and run all cells. It iterates all result folders, parses JSON from raw model responses, time-aligns with ground truth using `pd.merge_asof` (tolerance = 200 ms), and exports metrics to `Analysed/`.

#### 3. Visualize

- `plot_temporal.ipynb` — generates temporal profile figures
---

### Evaluation Metrics

| Metric | Description |
|--------|-------------|
| **MAE** | Mean Absolute Error — average absolute difference between prediction and ground truth |
| **RMSE** | Root Mean Squared Error — more sensitive to large errors |
| **TMS** | Trend Matching Score — fraction of steps where `sign(Δprediction) == sign(Δground_truth)` |

Time alignment: `pd.merge_asof(..., tolerance=200)` — nearest-neighbor match within 200 ms.

---

### Typical Workflow

1. Prepare videos and label Excel files under `Dataset/` as described above.
2. Set `GOOGLE_API_KEY` and `OPENAI_API_KEY` environment variables.
3. Run `Call_Gemini.ipynb` and `Call_GPT.ipynb` to generate raw results.
4. Run `Analyse.ipynb` to compute MAE / RMSE / TMS → exported to `Analysed/`.
5. Run `plot_temporal.ipynb` to generate figures.
